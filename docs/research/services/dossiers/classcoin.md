# ClassCoin Product Anatomy

기준일: 2026-11-08  
범위: 공식 홈페이지, 사용 가이드, 공개 블로그, 공개 업데이트.  
실측 상태: 로그인 후 실제 화면·클릭수·반응속도 미측정.

## 1. 제품 경계와 정체성

**E1 확인**  
ClassCoin은 단순 학급화폐 앱이 아니라 **학급경영 + 경제교육 + 학습/퀴즈 + 게임화**를 한 서비스에 결합한 올인원 구조다.

공개 기능군:
- 점수판
- 학생관리
- 퀘스트
- 루틴
- 직업
- 아이템상점
- 저축/세금/국고
- 부동산
- 투자
- 경매/창업
- 학급 온도계
- 대시보드/가계부
- 팜타이쿤
- 펫
- 퀴즈/브레인런
- 대출
- 쪽지/공지/미션보드
- 설정/실험실

제품 철학은 ‘교실 속 작은 사회’를 만든다는 쪽에 가깝다.

## 2. 사용자 역할

**E1 확인**
- 교사: 학급 개설, 학생 관리, 지급/회수, 직업/급여, 경제 정책, 상점, 세금/국고, 자산 조정, 학습활동 설정.
- 학생: 학급코드로 입장, 직업/퀘스트/상점/은행/게임/투자 등 참여.

**I 추론**
교사 계정 안에 실제로는 여러 운영 역할이 겹친다.
- 즉시 피드백 운영자
- 경제 관리자
- 상점 관리자
- 수업활동 관리자
- 자산/거래 감사자

따라서 역할 전환 비용을 UI가 흡수해야 한다.

## 3. 핵심 도메인 객체

공개 기능을 기준으로 최소 다음 객체가 연결된다.

- Class

- Transaction
- Job

- Quest
- Routine
- Store item
- Purchase
- Savings product
- Interest

## 5. 정보구조

**E1 확인**  
공식 가이드는 기능을 큰 영역으로 나누고, 교사용/학생용 가이드를 별도로 제공한다.

2026-10-26 업데이트:
- 설정을 학급/활동/소통으로 재정리
- 실험실 메뉴·놀이 카드 숨김
- 학생 메뉴 왼쪽 펼침/스크롤 개선

이는 기능 증가 시 **정보구조를 다시 정리하는 작업 자체가 핵심 제품 기능**임을 보여준다.

### D Class Money 적용
1차 메뉴를 기능명이 아니라 사용빈도로 배치:
- 오늘
- 학생
- 경제 운영
- 학습 모듈
- 기록
- 설정

저빈도 모듈은 활성화 전 완전히 숨긴다.

## 6. 대표 교사 플로우

### A. 수업 중 즉시 지급
**E1 확인**
점수판을 태블릿/PC/스마트폰에 띄우고 학생 이름 터치로 즉시 점수 지급.

**UX 해석**
경제 전체를 열지 않고 ‘지금 필요한 행동’만 분리한 kiosk/quick-action surface다.

### B. 직업/자동급여
공식 블로그는 직업별 급여와 자동 주기 지급, 업무 체크리스트를 설명한다.

흐름:
직업 정의 → 학생 배정 → 지급주기 → 수행 → 자동급여 → 가계부.

### C. 세금/국고
세금 자동징수 → 국고 적립 → 정기지출/공동체 사용.

2026-10-26에는 누진세·세제혜택을 저장하기 전에 학생별 대상과 금액 예시를 확인하도록 개선됐다.

**핵심 패턴:** 복잡한 정책은 설정 → 영향 미리보기 → 적용.

## 7. 상태 모델

공개 업데이트에서 다음 상태 구분이 드러난다.
- 직업 지원: 신청/배정/과거 기록
- 알림: 정상처리/조회실패/재조회
- 급여: 지급일/변경
- 팜코인: 사용/전환/종료/보존/소멸
- 상점: 판매/후기/사용수량 제한

**D 제안**
Class Money는 상태를 데이터 모델로 명시:
PENDING / ACTIVE / COMPLETED / FAILED / REVERSED / EXPIRED.

## 8. 자동화와 예약

**E1 확인**
- 자동 급여
- 자동 이자
- 자동 세금
- 국고 정기지출
- 퀘스트/루틴 일정
- 일부 게임/보상 규칙

자동화가 많아질수록 사용자가 현재 상태를 잊기 쉽다.

### D 제안
자동화 화면에:
- 다음 실행일
- 최근 실행결과
- 영향 학생 수
- 다음 예상 금액
- 일시정지
를 항상 제공.

## 9. 복잡성을 풀어낸 방식

1. 기능군별 메뉴 분리
2. 교사/학생 가이드 분리
3. 기능 숨김
4. 설정 도메인별 재그룹화
5. 복잡한 경제규칙의 영향 미리보기
6. 수업 중 Quick UI
7. 경제재화와 일부 게임재화 분리

특히 팜코인 모드에서 학급화폐와 별도 재화를 선택할 수 있는 점은 ‘게임 참여’와 ‘경제학습 데이터’를 분리하는 구조로 참고할 만하다.

## 10. UI/UX 리스크

### A. 메뉴 폭증
고급 금융·학습·게임이 동시에 노출되면 학생이 핵심 경로를 잃을 수 있다.

### B. 화폐 의미 혼합
행동보상, 학습보상, 직업급여, 게임, 투자 수익이 모두 같은 화폐로 합쳐지면 ‘왜 돈이 생겼는가’의 의미가 흐려질 수 있다.

### C. 자산 격차 강화
투자/부동산/창업/경매가 기존 부유 학생에게 더 많은 기회를 줄 수 있다.

### D. 현실 권리의 상품화
자리·사물함을 경제 자산으로 다룰 때 교육환경의 기본권과 충돌할 수 있다.

## 11. 교육 모델

공식 블로그는:
- 소득과 노동
- 소비와 기회비용
- 저축
- 세금과 공공재
- 인플레이션
- 수요·공급
- 창업
을 학급화폐로 경험시키는 방향을 제시한다.

Class Money가 가져갈 핵심은 ‘기능’보다 **한 기능이 어떤 경제 개념을 체험시키는지 명시하는 방식**이다.

## 12. 확장 구조에서 얻는 핵심 교훈

ClassCoin은 Class Money의 **장기 확장 상한**을 보여준다.

초기부터 따라가면 안 될 것:
- 투자
- 실제 시세연동
- 부동산
- 대출
- 랜덤상자
- 여러 게임

먼저:
지갑 → 직업/급여 → 상점 → 거래내역 → 저축 → 공동체.

그 다음 학습모듈로 확장.

## 13. Class Money에 가져올 것

**강하게**
- quick award surface
- 자동급여
- 세금→국고
- 설정 영향 미리보기
- 기능 숨김
- 학생/교사 UI 분리
- 경제와 게임재화 분리
- 가계부/자산 통합 조회

**변형**
- 부동산 → 가상 자산 시나리오
- 투자 → 폐쇄형 모의시장
- 창업 → 프로젝트형 학생 상점

**제외 권고**
- 실제 시세연동
- 공개 자산 경쟁
- 필수 좌석/휴식 상품화
- 확률형 경제보상

## 14. Craft Anything 실측 과제

- 교사 dashboard의 실제 1차 메뉴 수
- 수업 중 지급: 개인/모둠/전체 각 클릭수
- 학생 홈 첫 화면 정보 우선순위
- 직업 등록→배정→자동급여 설정
- 세금 설정→미리보기→적용
- 국고 지출 흐름
- 학생 가계부/자산조회
- 기능 숨김 전후 navigation
- mobile/tablet/desktop 3폭 capture
- 실패 알림의 재조회/복구 UX

## 15. 현재 판단

ClassCoin의 가장 큰 강점은 **기능 확장성**이고 가장 큰 설계 과제도 **기능 확장성**이다.

Class Money는 이 확장 범위를 참고하되, 기본 경험은 훨씬 좁고 명확하게 유지해야 한다.
