# ClassCoin 심층 분석

기준일: 2026-11-08  
분석 유형: 공개 공식 홈페이지·가이드·블로그 기반 Clean Room 문헌 분석  
실측 상태: 로그인 후 실제 조작·클릭 수·반응 시간은 미측정

## 1. 왜 분석하는가

ClassCoin은 Class Money와 가장 직접적으로 겹치는 국내 비교 대상이다. 단순 포인트 앱이 아니라 직업·급여·저축·세금·국고·상점·경매·부동산·투자·창업·기부·게임까지 하나의 학급 운영 환경에 넣고 있다. 따라서 “무엇을 넣을까”보다 “기능이 많아졌을 때 무엇을 기본으로 보이고 무엇을 숨길까”를 분석하는 데 가치가 크다.

## 2. 제품 정체성

공식 홈페이지는 서비스를 ‘학급 자동화 + 교실 속 작은 경제’로 설명한다. 경제 시스템만 제공하지 않고 점수판, 퀘스트, 루틴, 공지, 체크리스트, 퀴즈, 펫 같은 학급경영 기능과 결합한다.

이 구조의 장점은 교사가 여러 서비스를 오가지 않아도 된다는 점이다. 반대로 Class Money가 이 범위를 그대로 따라가면 경제교육 제품의 정체성이 흐려질 수 있다.

## 3. 확인된 핵심 경제 루프

1. 교사가 학생에게 점수·퀘스트 보상 또는 직업 급여를 지급한다.
2. 학생은 학급화폐를 보유한다.
3. 상점, 저축, 세금, 기부, 부동산, 투자 등으로 화폐가 이동한다.
4. 국고와 각종 자산으로 돈의 위치가 분산된다.
5. 창업·거래·경매 등으로 학생 간 시장 활동이 확장될 수 있다.

이 서비스의 핵심 특징은 ‘화폐의 지출처’를 매우 많이 만든다는 점이다. 단순 보상 포인트처럼 잔액이 계속 쌓이는 문제를 다양한 경제 활동으로 해소하려는 구조다.

## 4. 교사 운영 관점

확인된 장점:
- 수업 중 이름 터치만으로 즉시 점수를 지급하는 키오스크형 점수판.
- 직업별 자동 급여.
- 저축 상품의 자동 이자.
- 세금 자동 징수.
- 국고 정기지출.
- 학생별 자산 조정과 가계부 조회.
- 직업 지급일 달력·설정.
- 체크리스트 담당 학생 지정 등 학생 역할 위임.

2026-10-26 업데이트에서 설정 메뉴를 학급·활동·소통으로 재정리하고 실험실 메뉴와 놀이 카드를 숨길 수 있게 한 점이 특히 중요하다. 기능 증가 자체가 탐색 비용을 만들었기 때문에 ‘숨김/그룹화’가 제품 기능이 된 것으로 해석할 수 있다.

Class Money 시사점:
- 기능이 늘어날수록 메뉴 추가가 아니라 기능 가시성 관리가 필요하다.
- 교사 홈에는 경제의 모든 메뉴가 아니라 ‘오늘 처리할 일’을 먼저 보여주는 편이 낫다.
- 수업 중 즉시 지급은 별도 최소 UI로 제공할 가치가 크다.

## 5. 학생 경험 관점

ClassCoin은 학생이 수동적으로 포인트를 받기만 하는 구조에서 벗어나 직업, 상점, 기부, 은행, 투자, 부동산, 창업 등 다양한 경제 주체가 되도록 설계한다.

장점:
- 화폐를 쓸 이유가 많다.
- 학생이 장기적으로 서비스를 탐색할 동기가 생긴다.
- 교실이 작은 사회처럼 확장된다.

주의:
- 경제 핵심 개념보다 수집·게임·투자 요소가 더 강하게 동기를 만들 가능성이 있다.
- 초등학생에게 원리금균등, 중도상환수수료, 신용등급 등의 고급 금융 개념은 학습 목표와 학년 수준에 따라 과부하가 될 수 있다.
- 아바타·펫·행운상자 등은 재미 요소지만 경제 학습 재화와 동일 화폐로 결합할 경우 학생의 목표가 ‘재무적 선택’보다 ‘게임 보상 획득’으로 이동할 수 있다.

## 6. 경제 엔진 관점

특히 주목할 요소:
- 저축과 이자
- 세금과 국고
- 누진세 및 세제 혜택
- 국고 정기지출
- 직업 급여
- 재산/부동산
- 창업
- 투자
- 기부 온도계

2026-10-26 업데이트에서 자산·신용등급에 따라 누진세·세제혜택을 계산하고 저장 전에 학생별 예상 금액을 확인하도록 한 것은 매우 좋은 패턴이다.

Class Money 적용:
‘경제규칙 변경 → 즉시 적용’이 아니라 ‘변경 전 영향 미리보기’를 표준으로 삼는다.

예:
- 기본급 50 → 40
- 세율 10% → 15%
- 영향을 받는 학생 25명
- 학생별 예상 실수령 변화
- 대표 상품 구매 예상 기간 변화

## 7. 게임 재화 분리에서 얻는 중요한 교훈

팜타이쿤의 팜코인을 학급화폐와 분리해 선택할 수 있게 한 점은 매우 중요하다.

Class Money 권고:
- 경제교육 화폐: 급여·저축·소비·세금·예산
- 게임/꾸미기 재화: 필요하면 별도
- 두 재화를 기본적으로 환전하지 않음

이렇게 해야 경제 학습 데이터가 게임 참여량에 의해 왜곡되지 않는다.

## 8. 교육적으로 비판할 부분

공식 블로그에서는 자리 부동산 경매, 직업 경매, 투자, 학급 주식회사 등을 경제교육 활동으로 제안한다. 아이디어 자체는 경제 개념을 체험하게 할 수 있지만 Class Money가 그대로 채택해서는 안 된다.

특히:
- 자리를 돈으로 구매/임대하면 실제 학습환경의 형평성과 충돌할 수 있음.
- 높은 자산을 가진 학생이 인기 직업·좋은 자리·투자 기회를 더 얻으면 부의 자기강화가 발생함.
- 공개 경매는 자산 격차를 공개적으로 드러낼 수 있음.
- 실제 시세 연동 투자와 가상자산은 경제교육보다 가격 변동 게임으로 소비될 위험이 있음.
- 행운상자 같은 확률형 콘텐츠는 경제 화폐와 분리해도 신중해야 함.

## 9. Class Money에 가져올 것

강하게 도입 검토:
1. 한 반 안에서 직업→급여→소비→저축→공동체 흐름 연결
2. 자동 급여와 자동 거래
3. 세금→국고→공공 지출의 가시화
4. 경제규칙 변경 전 학생별 영향 미리보기
5. 기능 숨김/단계별 개방
6. 교사용 빠른 지급 모드
7. 학생 역할을 실제 운영과 연결
8. 게임 재화와 경제 화폐 분리

변형해서 도입:
- 부동산 → 실제 좌석 대신 가상의 자산 시뮬레이션
- 창업 → 학생 서비스/가상 상품 프로젝트
- 투자 → 실제 종목 연동보다 교사가 통제하는 모의 시나리오
- 경매 → 학습 시나리오에서 일시적으로 사용

초기에는 제외:
- 실제 주식·금·가상자산 시세 연동
- 확률형 행운상자
- 공개 자산 경쟁
- 좌석·휴식·학습권의 경제적 상품화

## 10. Craft Anything 후속 실측 과제

공개 계정 또는 정당한 체험 계정이 있을 때 다음을 동일 조건으로 관찰:
- 새 학급 생성부터 학생 25명 등록까지 단계 수
- 점수판에서 개인/모둠/전체 지급 클릭 수
- 직업 5개와 자동급여 설정 시간
- 저축상품 생성과 이자 설정 방식
- 세금 설정 후 영향 미리보기 화면
- 학생 상점 구매 과정
- 교사가 오지급을 정정하는 과정
- 학생 자산/거래내역의 개인정보 노출 범위
- 모바일 360, 태블릿 768, PC 1280px
- 기능 숨김 전/후 메뉴 복잡도

## 11. 현재 판단

ClassCoin은 ‘Class Money가 언젠가 어디까지 확장될 수 있는가’를 보여주는 가장 좋은 국내 사례다. 그러나 Class Money의 초기 방향은 ClassCoin보다 기능을 적게 만드는 것이 아니라, 경제 학습의 핵심 루프를 더 명확하게 만드는 쪽이 적절하다.

핵심 차별화 후보:
‘게임화된 학급경영 플랫폼’이 아니라 ‘교사가 쉽게 운영하고 학생이 자신의 경제적 선택을 이해하는 교실 경제 실험실’.

## 심화 보완: 12개 분석축

### A. 사용자와 권한 모델

공개 정보에서 최소한 교사와 학생 역할이 명확히 구분되고, 교사는 카카오/Google 로그인, 학생은 학급 코드 기반 입장을 제공한다. 최근 패치에는 교사가 담당 학급의 학생 가게를 편집하거나 후기 관리, 장부 검사 담당 배정 등을 수행하는 내용이 나타난다.

Class Money 설계에서 이 구조를 세분화하면 다음 권한이 필요하다.

- 교사 소유자: 경제규칙, 학생, 원장, 상점, 직업, 세금 등 전체 관리
- 공동교사: 학급경제 운영 가능, 구조적 설정 일부 제한 가능
- 학생: 본인 지갑·직업·주문·저축 중심
- 학생 보조역할: 은행원·상점관리자 등 제한권한
- 공개 점수판/프로젝터: 최소 정보만 표시하는 별도 읽기 전용 모드

중요한 원칙은 교육상 역할과 시스템 권한을 분리하는 것이다. '은행원'이라는 학생 직업을 가졌다고 해서 다른 학생의 전체 자산을 수정할 수 있어서는 안 된다.

### B. 핵심 상태전이

ClassCoin의 기능범위를 보면 Class Money는 최소 다음 상태기계를 독립적으로 설계해야 한다.

직업:
초안 → 모집중 → 지원 → 배정 → 근무중 → 급여예정 → 지급 → 계약종료

퀘스트:
초안 → 공개 → 수락/참여 → 완료제출 → 확인 → 보상 → 종료

상점:
상품활성 → 주문 → 승인/자동결제 → 사용/전달 → 취소/환불

저축:
개설 → 납입 → 유지 → 이자예정 → 이자지급 → 해지

세금:
정책초안 → 영향미리보기 → 활성 → 징수예정 → 징수 → 국고유입 → 공공지출

대출:
신청 → 심사 → 실행 → 상환중 → 완납/연체

기능을 많이 넣을수록 이 상태를 단순 boolean으로 처리하면 오류가 늘어난다.

### C. 교사 Jobs-to-be-Done

교사가 원하는 것은 '경제 기능을 쓰는 것'이 아니라 다음 업무를 빠르게 끝내는 것이다.

- 수업 중 학생 몇 명에게 즉시 지급
- 반복 직업급여를 잊지 않고 처리
- 잘못 지급한 돈을 안전하게 되돌리기
- 학생 경제가 과도하게 팽창하거나 고갈되는지 확인
- 상점·시장 분쟁을 최소화
- 세금 같은 복잡한 제도를 설명 가능하게 설정
- 학생별 자산이 아니라 학급 전체 경제상태를 파악

따라서 Class Money 교사 홈은 메뉴 모음보다 오늘 할 일 중심이어야 한다.

### D. 학생 Jobs-to-be-Done

학생은 다음 질문에 즉시 답할 수 있어야 한다.

- 지금 쓸 수 있는 돈은 얼마인가?
- 왜 이 돈을 받았거나 잃었는가?
- 다음 급여는 언제인가?
- 내가 맡은 직업은 무엇인가?
- 무엇을 살 수 있는가?
- 지금 사면 저축목표가 얼마나 늦어지는가?
- 내가 낸 세금은 어디로 갔는가?

기능 수가 많아도 이 일곱 질문이 어렵다면 경제교육 UX는 실패한다.

### E. 경제 인센티브 분석

ClassCoin은 수입원과 지출처가 많아 경제가 장기간 순환할 조건을 갖춘다. 반대로 수입 기능이 게임·퀴즈·퀘스트로 계속 늘어나면 통화량이 빠르게 증가할 수 있다.

Class Money에는 교사용 인플레이션 진단이 필요하다.

- 지급/회수 비율
- 학생당 중앙 잔액 증가율
- 대표 상점상품의 구매 가능 기간
- 미사용 화폐 비율
- 자산격차 추세

단순 '총 통화량이 많다'보다 경제가 실제로 소비·저축·순환되고 있는지를 봐야 한다.

### F. 실패모드와 복구

확장형 경제에서 반드시 시험할 오류:

- 급여일 변경 중 중복지급
- 직업 삭제 후 과거 지원 알림
- 주문 후 가격 변경
- 세금 정책 변경 직전/직후 중복징수
- 예금 이자 지급 중 실패
- 학생 탈퇴 후 자산/대출 기록 고아화
- 학급 종료 후 예약작업 실행
- 시장 거래 중 한쪽만 반영
- 국고 잔액 부족 상태의 자동지출

최근 직업 지원 알림 오류 패치가 존재한다는 점은 상태수명주기와 과거참조 처리가 실제 서비스에서 중요한 문제임을 보여준다.

### G. UI 정보구조

ClassCoin처럼 기능이 매우 많아질 경우 Class Money는 메뉴를 다음 4층으로 분리하는 것이 적합하다.

1. 오늘: 지급, 승인, 예정작업, 경고
2. 경제: 지갑, 직업, 상점, 저축
3. 수업모듈: 세금, 시장, 자산, 대출
4. 관리: 학생, 정책, 원장, 내보내기

학생은 현재 활성화된 모듈만 보도록 하며, 아직 배우지 않은 금융기능은 숨긴다.

### H. 데이터 모델 시사점

ClassCoin 수준의 확장을 염두에 둔다면 단일 balance 필드만으로 시작해서는 안 된다.

필요한 기반:
- 불변 거래원장
- account 단위 분리
- transaction source
- 정책 버전
- 예약작업 실행기록
- order/contract/application 별도 객체
- asset ownership
- audit event

잔액은 결과값이며 원장의 원인이 아니다.

### I. 교육적 위험

가장 큰 위험은 경제의 복잡성보다 경제가 학생의 실제 권리와 관계를 지배하게 되는 것이다.

검토가 필요한 것:
- 실제 좌석의 매매/임대
- 친구간 서비스 거래
- 신용등급 공개
- 자산순위
- 랜덤상자
- 성적/퀴즈 성과의 큰 금전보상
- 대출 실패를 행동평가로 연결

경제는 실패해도 안전한 시뮬레이션이어야 한다.

### J. Class Money 제품결정

Adopt:
- 통합 화폐원장
- 직업 자동급여
- 정책 영향 미리보기

Adapt:

Avoid by default:

### K. 경쟁전략

Class Money가 ClassCoin보다 기능이 적다는 것은 약점이 아닐 수 있다. 핵심은 '학급경영 전체' 대신 '경제적 선택을 배우는 가장 명료한 교실은행'이라는 좁고 강한 포지셔닝이다.

초기 경쟁력은 기능 수가 아니라:

- 학생이 거래 이유를 이해
- 경제 밸런스 자동진단
에서 만들어야 한다.

- 교사 지급이 몇 클릭인지
- 학생간 거래 안전장치 수준
- 세금/시장 기능의 실제 기본값
- 모바일 접근성
- 거래 되돌리기 범위

이 항목은 Craft Anything Clean Room 실측의 우선순위로 유지한다.

## V4 심층 해부 — 복잡한 경제의 운영가능성

### 1. ClassCoin은 단일 경제가 아니라 여러 경제권을 겹친다

공개 기능을 보면 하나의 학급화폐 안에:
- 교사 보상
- 직업급여
- 저축/이자
- 세금/국고
- 부동산
- 투자
- 창업/상점
- 경매
가 들어가고, 팜타이쿤은 별도 팜코인으로 학급화폐와 분리할 수도 있다.

이것은 중요한 설계 신호다.
모든 게임·활동을 한 통화에 연결하면 경제 인플레이션과 동기 왜곡이 커질 수 있어 별도 재화를 두는 것이 유리할 때가 있다.

Class Money는 통화를 최소 세 범주로 개념화할 필요가 있다.

- core currency: 교실경제 학습용
- activity currency: 특정 게임/이벤트용
- public fund: 세금과 공공지출용

기본은 core 하나만 쓰고, activity currency는 필요한 모듈에서만 별도로 생성한다.

### 2. 기능 확장보다 중요한 것은 ‘숨길 수 있는가’

2026-10-26 업데이트에는 설정 메뉴 재분류, 실험실/놀이 카드 숨김, 학생 메뉴 정돈 등이 포함된다.

이것은 기능이 많아질수록 정보구조가 핵심 문제가 된다는 것을 보여준다.

Class Money는 처음부터 다음 원칙을 채택해야 한다.

- inactive module은 학생 메뉴에서 완전히 숨김
- teacher-only advanced settings는 별도 영역
- experimental 기능은 기본 노출 금지
- ‘경제’와 ‘게임’ 메뉴를 분리
- 핵심 업무는 오늘 화면에 집중

### 3. 세금은 계산기보다 정책 시뮬레이터가 된다

ClassCoin은 2026-10-26 업데이트에서 누진세/세제혜택 규칙 저장 전에 학생별 대상과 금액 예시를 확인할 수 있게 했다.

이 패턴은 매우 강력하다.

Class Money의 세금 설정은 단순 tax rate 입력이 아니라 정책 실험도구가 될 수 있다.

교사가 규칙을 바꾸기 전:
- 총 세수
- 국고 변화
- 학생별 예상 세금
- 가장 부담률이 높은 구간
- 세금 후 가용잔액
- 예상 공공지출 가능액

을 보여준다.

학생 수업에서는 같은 화면의 단순 버전으로:
‘정액세와 비례세 중 어떤 것이 더 공정하다고 생각하나요?’
같은 토론으로 연결할 수 있다.

### 4. 시장경제가 열리는 순간 제품 성격이 바뀐다

창업과 학생 상점, 후기, 마켓플레이스는 교사→학생 경제를 학생↔학생 경제로 바꾼다.

그 순간 필요한 시스템도 달라진다.

추가로 필요한 것:
- seller identity
- listing
- inventory/service capacity
- buyer order
- dispute
- moderation
- review policy
- price control
- transaction limit

즉 학생시장 기능은 상점에 옵션 하나 추가하는 수준이 아니다. 별도의 Marketplace Domain이다.

Class Money 로드맵에서는 P2/P3로 분리하는 것이 적절하다.

### 5. 부동산은 경제적으로 흥미롭지만 교육적 권리와 충돌할 수 있다

자리·사물함의 소유/임대는 소유권과 임대료를 매우 직관적으로 보여준다.

그러나 실제 교실의 자리와 사물함은:
- 시력
- 이동지원
- 특수교육 지원
- 교사 배치
와 관련된 교육적 자원이다.

따라서 Class Money에서는 실제 좌석을 경제자산으로 쓰는 기능을 기본적으로 배제하고, 가상의 공간/건물을 사용하는 편이 안전하다.

핵심 개념은 남기고 실제 권리 충돌은 제거한다.

### 6. 통화량 관리가 고급 기능의 기반

직업, 퀘스트, 퀴즈, 게임, 창업이 모두 수입원이 되면 교사는 돈이 얼마나 발행되는지 감을 잃기 쉽다.

Class Money는 경제 건강도를 교사에게 다음처럼 보여줘야 한다.

- 지난 4주 신규 발행
- 지난 4주 상점/세금 회수
- 순증가 화폐량
- 중앙값 잔액 변화
- 상위/하위 20% 격차 변화
- 대표 상품 구매가능 기간 변화

중요:
개인 자산순위는 학생에게 공개하지 않지만 분포는 교사가 시스템 조정용으로 볼 수 있다.

### 7. ‘보상 상한’은 인플레이션 제어 장치이기도 하다

2026-10-26 퀴즈 보상에 점수비례, 보상상한, 학급 총보상 비례 설정이 추가됐다는 공개 기록이 있다.

이것은 단순 게임설정이 아니라 경제통화량 제어다.

Class Money의 모든 대량 보상 기능에는:
- per student cap
- per event cap
- class total cap
을 선택적으로 둘 가치가 있다.

### 8. 실패모드가 제품 복잡성을 보여준다

2026-10-13 패치에서 이미 삭제된 직업의 과거 지원 알림 조회가 서버오류를 만들었던 사례가 공개되어 있다.

이 사례가 보여주는 구조적 문제:
객체가 삭제되어도 과거 이벤트가 그 객체를 참조할 수 있다.

Class Money 데이터 원칙:
- 직업/상품을 hard delete하지 않음
- inactive/archived 상태
- 과거 거래는 snapshot title 저장
- notification은 참조객체가 없어도 렌더링 가능

이는 모든 경제 객체에 적용한다.
