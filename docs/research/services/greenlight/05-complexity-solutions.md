# Greenlight — 얽힌 문제와 해결방식

## 복잡한 문제를 어떻게 풀었는가

| 얽힌 문제 | 서비스의 해결방식 | Class Money에 번역 |
|---|---|---|
| 수입 후 계획이 늦어짐 | Income 시점 Allocation | Payday 직후 학생 배분. |
| 자율/통제 이분법 | 행동별 permission toggle | 학생간 송금·저축인출·고액구매 각각 정책. |
| 잘못된 배분규칙 | 100%/category compatibility save-time validation | 규칙 저장 전에 domain validation. |
| 공동체 일이 모두 유급화될 위험 | Chore reward type 구분 | 무보수 공동책임/정기직업/추가유급 task 분리. |

## 평가 기준

좋은 해결방식인지 판단할 때:
- 교사 클릭 수만 줄였는가, 아니면 오류복구도 쉬운가?
- 학생에게 필요한 사고까지 자동화해 없애지는 않았는가?
- 다수 학생에게 적용할 때 batch/exception을 처리할 수 있는가?
- 역할/권한/경제상태가 섞여 있지 않은가?
- 정상경로뿐 아니라 실패·취소·환불·정정도 정의돼 있는가?
- 기능이 증가해도 기본 사용자에게 복잡도가 전파되지 않는가?
