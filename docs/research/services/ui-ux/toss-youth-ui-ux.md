# 토스 유스 — 기능 얽힘·UI·UX 심층 분석

기준일: 2026-11-08  
분석 목적: 한국 어린이·청소년용 **전용 홈·잔액 경계·소비 회고·목표 UI** 분석  
주의: 실제 금융제품이므로 Class Money는 금융기능 자체가 아니라 정보구조와 상호작용 원리를 참고한다.

## 1. 복잡성의 본질
토스 전체 서비스는 매우 방대하지만 미성년 사용자에게 그대로 노출하지 않는다. 특히 14세 미만에는 성인과 다른 Youth Home을 제공해 필요한 기능만 남긴다고 토스가 설명한다.

\`\`\`mermaid
flowchart LR
 M[충전/받은 용돈] --> B[사용 가능 잔액]
 B --> C[카드 소비]
 B --> G[목표 저금통]
 C --> L[용돈기입장]
 L --> R[소비 습관 회고]
 P[보호자] --> M
 P --> CTRL[카드/안전 관리]
\`\`\`

가장 중요한 UX 전략은 **큰 플랫폼 안에서 아동에게 별도 정보구조를 제공하는 것**이다.

## 2. Youth Home — 기능 삭제가 아니라 역할별 IA
토스는 어린 사용자의 홈을 성인 홈과 다르게 단순화한다.

Class Money 적용:
교사 UI를 CSS로 축소해 학생에게 보여주는 방식이 아니라 routing/navigation부터 별도 설계.

교사 홈:
오늘 처리할 일 / 학생 / 경제운영 / 장부 / 설정.

학생 홈:
내 돈 / 최근 변화 / 목표 / 할 일 / 상점.

## 3. 잔액 경계를 문장으로 명확하게
공식 유스카드는 ‘충전한 만큼만 쓴다’는 메시지를 반복한다.

이 표현은 복잡한 선불카드 원리를 사용자가 이해할 수 있는 한 문장으로 바꾼다.

Class Money:
“지금 쓸 수 있는 돈만 사용할 수 있어요.”
“저축에 넣어둔 돈은 사용 가능 금액에 포함되지 않아요.”
처럼 시스템 규칙을 plain language로 설명.

## 4. 용돈기입장 — 거래목록을 회고 UI로 변환
토스는 단순 거래내역을 넘어서:
- 어디에 얼마나 썼는지
- 평소보다 많이 쓴 날
- 아낄 수 있는 내역
등을 보여 소비습관을 돌아보게 한다.

Class Money:
거래내역과 ‘이번 주 돌아보기’를 분리하지 않고 연결.

학생:
- 이번 주 들어온 돈
- 이번 주 쓴 돈
- 가장 큰 지출
- 목표에 넣은 돈
- 지난주와 달라진 점

단, 교실경제의 가격은 교사가 만든 것이므로 ‘과소비’라고 자동 판단하지 않는다.

## 5. 해냄 저금통 — 목표를 감정적으로 구체화
목표 이름/금액/남은 금액을 시각적으로 보여준다. ‘저축’이라는 추상 행위보다 ‘무엇을 위해 모으는가’를 앞세운다.

Class Money:
목표 카드에는:
- 목표 이름/이미지
- 현재/목표액
- 남은 금액
- 현재 저축속도 기준 예상기간
- 최근 추가한 금액
을 표시.

## 6. 금융 학습의 별도 층
Money Study Café처럼 실제 금융행동 화면과 학습 콘텐츠를 별도 섹션으로 두되 동일 앱 안에서 연결한다.

Class Money:
학생이 세금 기능을 처음 열 때:
[간단 설명] → [활동] → [실제 시뮬레이션]
으로 연결.

## 7. 실제 투자와 모의 투자 구분에서 배울 점
토스는 청소년 영역에서 실제 금융생활과 별도로 가상돈 기반 모의투자 경험도 제공한다고 설명한다.

Class Money 원칙:
‘시장 시뮬레이션’이 있더라도 기본지갑과 분리된 학습환경으로 두는 것이 안전하다.

## 8. 보호자 전용 기능 — 관리자 UI의 분리
보호자에게 용돈 보내기, 카드 분실신고 등 자녀에게 필요 없는 관리기능을 별도로 둔다.

Class Money 교사도:
학생은 볼 필요 없는:
- 학생 PIN 재발급
- 데이터 export
- 경제 규칙
- 감사 로그
를 관리자 영역으로 완전히 분리.

## 9. Safety UX
분실 시 앱에서 카드 정지, 한도, 보호자 승인처럼 ‘문제가 생겼을 때 사용자가 할 수 있는 행동’을 명확히 보여준다.

Class Money:
- 로그인코드 분실 → 재발급.
- 이상 거래 → 신고.
- 구매 오류 → 주문 상세.
- 잘못 지급 → 정정.
복구경로가 항상 눈에 보여야 한다.

## 10. UI 톤에서 배울 것
토스의 어린 사용자용 서비스는 어린이를 지나치게 유아적으로 다루기보다 실제 금융 서비스의 느낌을 유지하면서 설명을 단순화한다.

Class Money에서도 5~6학년에게 지나치게 캐릭터·게임 중심 UI를 강제하지 않는 편이 좋다.
저학년/고학년 시각 밀도를 조절할 수 있는 프리셋 검토.

## 11. Class Money 적용
- 학생 전용 Home/IA.
- ‘사용 가능’ 금액의 명확한 경계.
- 거래내역→소비 회고 연결.
- 목표 이름과 남은 금액 중심.
- 학습콘텐츠와 실제 시뮬레이션 연결.
- 관리자 기능 완전 분리.
- 오류 시 복구 행동을 즉시 노출.
- 아동용이더라도 지나친 유아화 지양.
