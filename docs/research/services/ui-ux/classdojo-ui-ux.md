# ClassDojo — 기능 얽힘·UI·UX 심층 분석

기준일: 2026-11-08  
분석 목적: 경제앱이 아닌 **수업 중 즉시 피드백 입력 UX**를 벤치마킹

## 1. 복잡성의 본질
교사는 수업 중 많은 학생에게 반복적으로 피드백해야 한다. 기능이 복잡해서가 아니라 **입력 빈도가 매우 높아 작은 마찰도 누적**되는 문제가 핵심이다.

\`\`\`mermaid
flowchart LR
 S[학생/모둠/전체 선택] --> K[Skill 선택]
 K --> P[Point 지급]
 P --> F[즉시 피드백]
 P --> R[Reports]
 P --> U[최근 Undo]
\`\`\`

## 2. 복잡함을 푸는 가장 강한 방식: 사전 정의
교사가 매번 이유·점수를 입력하지 않고 Skill에 이름과 값이 이미 정의된다.

Class Money에서는 이를 **지급사유 템플릿**으로 번역한다.
- 도서정리 +10
- 학급 운영 도움 +5
- 직업 특별업무 +10

즉 입력보다 ‘선택’을 중심으로 만든다.

## 3. 대상 범위의 통일
개인, 모둠, 전체를 서로 다른 기능으로 만들지 않고 같은 포인트 시스템의 대상만 바꾼다.

Class Money도:
- 개인
- 여러 명
- 모둠
- 전체
를 같은 지급 패널에서 처리.

중요:
‘모둠 구성원 각각 5 지급’과 ‘모둠 공동기금에 25 지급’은 경제적으로 다르므로 문구를 완전히 구분한다.

## 4. 최근 작업 Undo
ClassDojo는 마지막 지급 직후 빠른 Undo를 제공하고, 오래된 항목은 Reports에서 관리한다.

UX 원리:
**오류 수정 비용을 오류 발생 시점에 가장 낮게 만든다.**

Class Money:
지급 완료 snackbar:
“25명에게 각 5 지급 · 총 125”
[되돌리기]

내부적으로는 삭제가 아니라 reversal.

## 5. Reports — 빠른 입력과 상세 감사의 분리
수업 화면은 단순하지만 Reports에는 누가/언제/어떤 skill/어떤 범위로 지급했는지 더 상세한 문맥이 남는다.

Class Money 역시:
- 입력 UI는 가볍게
- 원장은 상세하게
설계해야 한다.

빠른 화면에 거래 ID나 복잡한 원장 필드를 노출할 필요는 없다.

## 6. 현재 표시값과 역사 기록의 분리
Redeem/Reset 같은 기능은 현재 표시 점수와 과거 기록을 분리한다.

Class Money에서:
- 학생이 보는 ‘사용 가능액’
- 기간별 요약
- 전체 감사원장
을 분리하되 금융 원장 자체는 reset하지 않는다.

## 7. 행동포인트와 경제화폐가 충돌하는 지점
ClassDojo의 구조는 행동피드백에 최적화돼 있다. 이를 그대로 돈으로 바꾸면:
- 교사가 많이 관찰한 학생이 더 부유해질 수 있음.
- 행동평가가 구매력으로 축적.
- negative point가 경제적 빈곤으로 이어짐.

따라서 Class Money는 UI 패턴만 가져오고 경제 의미는 분리.

## 8. Projection/공개 화면 문제
교실에서 점수판을 프로젝터에 띄우는 경험은 즉시 피드백에 좋을 수 있으나, Class Money 자산을 공개하면 사생활·낙인 문제가 생긴다.

공개 화면에는:
- 학급 공동 목표
- 경제 전체 화폐량
- 공동 국고
- 활동 진행
등만.

개인 잔액은 비공개.

## 9. Class Money 적용
- 학생 타일 기반 선택.
- 사유 템플릿.
- 개인/그룹/전체 공통 패널.
- 최근 Undo.
- 입력 UI와 감사 원장 분리.
- 공개 화면에는 개인 자산 제외.
- 행동 feedback과 경제화폐 분리.

## 10. UI 품질 목표
수업 중 지급은 ‘관리 업무’처럼 느껴지면 실패다.
목표:
대상 선택 → 사유 선택 → 완료.
고정 금액 사유라면 숫자 입력조차 생략.
