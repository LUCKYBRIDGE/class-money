# 토스 유스 — 얽힌 문제와 해결방식

## 복잡한 문제를 어떻게 풀었는가

| 얽힌 문제 | 서비스의 해결방식 | Class Money에 번역 |
|---|---|---|
| 복잡한 금융용어 | 행동언어 중심 Youth IA | 저학년/고학년 용어 프리셋. |
| 총자산과 구매가능액 혼동 | 충전한 만큼만 사용 | Available를 첫 화면 최우선. |
| 거래내역이 기록으로만 끝남 | Allowance Tracker 회고 | 주간 reflection layer. |
| 투자가 기본 경제를 왜곡 | Mock Investing 분리 | Simulation Lab 별도 account. |
| 문제 발생 후 행동이 불명확 | 안전/분실 복구 surface | 오류·분실·오지급 recovery action 노출. |

## 평가 기준

좋은 해결방식인지 판단할 때:
- 교사 클릭 수만 줄였는가, 아니면 오류복구도 쉬운가?
- 학생에게 필요한 사고까지 자동화해 없애지는 않았는가?
- 다수 학생에게 적용할 때 batch/exception을 처리할 수 있는가?
- 역할/권한/경제상태가 섞여 있지 않은가?
- 정상경로뿐 아니라 실패·취소·환불·정정도 정의돼 있는가?
- 기능이 증가해도 기본 사용자에게 복잡도가 전파되지 않는가?
