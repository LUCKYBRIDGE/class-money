# 반짝 모의투자 — 얽힌 문제와 해결방식

기준일: 2026-11-11

| 얽힌 문제 | 반짝 모의투자의 해결방식 | Class Money에 번역 |
|---|---|---|
| 45분 수업에서 학생 계정 생성이 너무 느림 | 학생별 QR/접속코드, 별도 학생회원가입 제거 | QR + short PIN 형태의 shared-device login |
| 교사가 20~30명 거래를 개별 확인하기 어려움 | 학급 수익률·포트폴리오 Dashboard | Teacher aggregate dashboard |
| 실제 금융개념이 추상적임 | 실제 거래소와 유사한 차트·호가·매수/매도 UI | 선택형 Simulation Lab에서 실제 mental model 사용 |
| 미국주식 가격을 바로 보여주면 환율 학습이 빠짐 | KRW/USD를 분리하고 직접 환전 | currency account + exchange transaction |
| 투자활동이 단순 게임이 됨 | 거래 이유·매매일지·수업 회고질문 | Action → Reason → Result → Reflection |
| 학생이 집에서 계속 거래할 수 있음 | 교사가 접속 가능 시간 설정 | teacher-controlled activity window |
| 종목이 너무 많아 데이터/선택부담 증가 | 1차 완성 당시 200 대표종목 + 교사 추가 | curated universe + teacher whitelist |
| 외부시세 직접 호출의 CORS/키 문제 | 초기설계에서 서버측 데이터 갱신 구조 제안 | quote provider adapter + server cache |
| 국장/미장의 시장·통화가 얽힘 | 시장 선택 + 별도 환전 탭 | Market과 Currency를 별도 domain으로 |
| 학습 성과가 수익률 하나로 축소될 위험 | 매매일지와 토론 질문 추가 | 수익률 외 근거·분산·회고 지표 |
| 학생마다 화면을 열어야 하는 관리문제 | 학생 row-level 입장/QR/수정/삭제 + Dashboard | roster row actions + batch controls |

## 1. 특히 좋은 해결: Login Friction 제거

학생용 실제 금융앱을 흉내내면서도:
- 회원가입
- 이메일
- ID 찾기
를 학생에게 요구하지 않는다.

이는 금융 UI의 현실감은 살리고 **학교 계정관리 마찰은 제거**한 좋은 절충이다.

## 2. 특히 좋은 해결: 환전을 별도 학습으로 남김

미장을 지원할 때 USD를 내부에서 자동환산해 숨길 수도 있었지만, 학생이 직접 환전하게 하여:
- 환율
- 기준통화
- 보유통화
를 경험하도록 만들었다.

이 선택은 “자동화하지 말아야 할 학습마찰”의 좋은 사례다.

## 3. 특히 좋은 해결: 교사가 수업 시간을 통제

가정용 금융앱과 교실용 서비스의 결정적 차이.

학생 자율서비스라면 24시간 access가 자연스럽지만 교실에서는:
- 수업 목적
- 과몰입
- 집에서의 반복거래
- 기기접근 격차
문제가 생긴다.

접속 가능 시간을 teacher control로 둔 것은 Class Money의 여러 고몰입 활동에도 적용할 가치가 크다.

## 4. 비판적 검토: 랭킹

현재 학생 IA와 홍보에서 랭킹이 중요한 위치를 차지한다.

### 위험
- 수익률이 높은 학생 = 투자능력이 높은 학생이라는 오해
- 단기 고위험 전략을 보상
- 공개 자산 비교
- 운과 실력을 혼동

### Class Money 권고
시장 Simulation에서 랭킹은:
- 기본 OFF
- 익명/팀 단위 선택
- 단순 수익률 대신 다양한 전략 비교
로 제한하는 편이 낫다.

## 5. 비판적 검토: 실제 시장과 닮을수록 생기는 문제

실제 증권앱과 유사한 화면은 몰입에 강하지만:
- 차트/호가의 단기 변동에 주의가 쏠림
- 기업가치/분산/장기투자가 뒤로 밀림
- 거래 빈도가 학습 참여처럼 보임

따라서 “실전 흡사” 자체가 교육적으로 항상 좋은 것은 아니다.

보완:
- 종목 선택 근거
- 위험요인
- 분산
- 투자기간
- 거래하지 않기 선택
도 학습 UX에 포함할 필요가 있다.

## 6. 비판적 검토: ‘실시간’ 표현

공개 자료 간:
- 1초 단위
- 10초 단위
표현이 다르다.

현재 landing은 구체 주기를 적지 않는다.

### Class Money 원칙
외부 데이터가 들어오는 모든 simulation은:
- quote provider
- last updated at
- delayed/realtime status
를 화면과 로그에 명시한다.

## 7. 비판적 검토: 시장 데이터 의존성

실제 시장 연결은 교육 몰입도를 높이지만:
- provider 장애
- API rate limit
- CORS
- scraping/이용조건
- 장 마감
- 미국시장 시차
- 환율 freshness

같은 운영문제를 만든다.

따라서 Class Money에서는 시장기능을 core economy와 분리해 **외부 provider 장애가 학급화폐 전체를 멈추지 않게** 해야 한다.
