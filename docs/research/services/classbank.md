# ClassBank 심층 분석

기준일: 2026-11-08  
분석 유형: 공식 도움말·가격·수업자료 기반 문헌 분석  
실측 상태: 실제 로그인 UI와 처리시간 미측정

## 1. 왜 분석하는가

ClassBank의 가장 큰 가치가 기능 수에 있지는 않다. 핵심은 교실경제를 ‘처음부터 완성된 거대한 시스템’으로 요구하지 않고 Bonuses, Jobs, Bills, Store라는 독립적인 부품으로 시작하게 한다는 점이다.

Class Money의 온보딩과 단계형 기능 설계에 가장 직접적인 참고 사례다.

## 2. 제품 정체성

공식 설명상 K-12 교실 경제 플랫폼이며 학급경영, 금융 리터러시, 긍정적 행동 전략을 결합한다.

핵심 경제 구성:
- Bonuses
- Jobs
- Bills
- Store
- Savings
- Interest
- Student Helpers

각 구성요소는 선택적으로 사용할 수 있다.

## 3. 온보딩 구조

공식 시작 가이드는 약 15분 설정을 목표로 하고 대부분의 교사에게 먼저 다음 네 가지를 추천한다.

1. Classes
2. Students
3. Bonuses
4. Classroom Store

Jobs, Bills, Savings/Interest, Co-teachers는 필요할 때 추가한다.

이 설계가 중요한 이유:
- ‘교실 경제를 시작하려면 은행·세금·직업을 전부 설정해야 한다’는 부담을 없앤다.
- 경제 운영 경험이 없는 교사도 포인트+상점 구조로 시작하고 이후 확장할 수 있다.
- 기능의 존재 여부와 기능의 노출 시점을 분리한다.

Class Money 적용:
Starter 모드에는 학생, 기본 지급, 상점, 거래내역만 보여주고 나머지는 ‘기능 추가’에서 연다.

## 4. 경제 밸런스 설계

2026년 공식 권장값:
K-2, 3-5, 6-12로 보너스·벌금·급여·상점 가격·비용 범위를 나눠 제시한다.

3-5 예:
- 월 소득 약 100
- 월 고정비 약 80
- 기본 자유사용액 약 20

핵심은 절대 금액이 아니라 공식 안내가 ‘급여를 고정비보다 조금 높게 설정하라’는 구조를 권장한다는 점이다.

Class Money 적용:
교사가 금액을 정하면 시스템이 자동으로 다음을 계산:
- 정기소득
- 필수/선택 정기지출
- 남는 자유금액
- 대표 상품을 사는 데 필요한 기간
- 구조적 적자 학생 수
- 예상 저축 가능액

단, ClassBank의 금액을 한국 교실 기본값으로 복사하면 안 된다.

## 5. 직업 시스템

학생은 직업에 지원할 수 있고 교사는 채용한다. 모든 학생이 직업을 갖지 않는 경우 ‘Student’ 직업을 만들어 전체 학생에게 기본 급여를 줄 것을 공식 가이드가 제안한다.

좋은 점:
- 직업 선택을 단순 교사 배정이 아니라 지원 과정으로 바꿈.
- 모든 학생의 기본 수입을 별도로 보장할 수 있음.
- 급여 자동화로 교사의 반복 업무 감소.

Class Money 권고:
- 기본 참여소득과 직업급여를 분리.
- 인기 직업은 무조건 최고급여가 되지 않도록 설계.
- 직업 순환일 표시.
- 직업 경험률을 교사에게 보여주기.
- 직업을 못 얻었다고 경제참여에서 제외되지 않게 하기.

## 6. Student Helpers가 매우 중요한 이유

2026년 Student Helpers:
- Store Clerk: 상점 승인, 상품 편집
- HR Representative: 직업게시판·직업 편집
- Banker: 거래 전송

이것은 ‘교실 직업’이 실제 시스템 운영 권한과 연결될 수 있음을 보여준다.

Class Money에서는 이 아이디어를 더 안전하게 구현해야 한다.

직업과 권한은 분리:
- ‘은행원’ 직업을 얻었다고 자동으로 타인 돈 변경 권한을 주지 않음.
- 교사가 Banker Helper 권한을 별도로 부여.
- 기간, 1회 한도, 하루 한도 설정.
- 자기 자신 지급 금지.
- 모든 조작 감사로그.
- 교사 즉시 권한 회수.

## 7. 학생 공동 설계

ClassBank는 학생들과 보너스, 벌금, 상품, 직업을 함께 만들 것을 권한다.

이것은 단순 참여 유도가 아니라 경제 규칙의 정당성을 높인다.

Class Money 적용:
‘경제 시작 회의’ 템플릿 제공:
- 우리 반에는 어떤 역할이 필요한가?
- 어떤 행동에 돈을 주는 것이 공정한가?
- 돈으로 살 수 없는 것은 무엇인가?
- 상점에는 무엇이 있어야 하는가?
- 벌금은 필요한가? 필요하다면 제한은?

## 8. Bills의 장점과 위험

공식 철학은 학생이 월세를 못 내더라도 교실 자원이나 참여권을 박탈하면 안 된다고 명시한다. 이는 매우 중요한 안전 원칙이다.

Class Money:
- 청구서는 기본 OFF.
- 활성화해도 실제 책상/자리/수업 참여를 박탈하지 않음.
- 미납은 학습 시나리오로 처리.
- 상환계획이나 회고를 제공할 수 있으나 학생을 공개 표시하지 않음.

## 9. 행동보상과 경제 화폐 결합 문제

ClassBank는 행동 보너스와 벌금을 경제 화폐에 직접 연결한다. 운영상 편리하지만 Class Money에서는 기본값으로 삼기 어렵다.

위험:
- 교사의 행동평가가 학생 자산 격차로 누적.
- 조용하거나 표현이 적은 학생이 보너스를 덜 받을 가능성.
- 벌금이 경제적 낙인으로 연결.

권고:
- 기본소득/직업급여가 경제의 주 수입원.
- 행동 보너스는 선택 기능.
- 개인 월간 보너스 상한과 편중 경고.
- 벌금은 기본 OFF.

## 10. UX적으로 가져올 핵심

- 단계적 설정
- 기능 선택형
- 자동급여
- 학생 지원→채용
- 학생 운영 역할
- 공동설계
- 경제 가격 가이드
- 안전한 ‘못 내도 괜찮다’ 철학

## 11. 그대로 가져오지 않을 것

- 미국 학년별 추천금액
- 숙제 면제 등 학습권 관련 상품
- 벌금을 기본 경제요소로 보는 구조
- 행동성과를 경제적 성공과 직접 동일시하는 구조

## 12. Craft Anything 후속 실측 과제

- 신규 반 생성부터 기본 경제 완성까지 실제 단계 수
- 학생 25명 입력 방식
- Bonus를 한 학생/모둠/전체에게 보내는 속도
- Jobs 지원과 채용 화면
- Auto Pay 실패/재실행 상태
- Bills 자동 청구 실패 처리
- Store 구매 학생 화면과 교사 승인 화면
- Student Helper가 실제 볼 수 있는 메뉴 범위
- Savings와 Interest의 학생 시각화
- 거래 정정/검색/필터 UX

## 13. 현재 판단

ClassBank에서 Class Money가 가장 강하게 배워야 할 것은 ‘기능’보다 ‘도입 순서’다.

Class Money의 첫 사용 경험은 경제 시스템 전체를 설정하는 과정이 아니라:
‘학생 등록 → 돈 지급 → 쓸 곳 하나 만들기 → 실제로 한 번 거래해보기’
가 되어야 한다.

## 심화 보완: 12개 분석축

### A. 사용자와 권한 모델

ClassBank는 교사, 학생, 공동교사, 학교관리자에 더해 Student Helper 역할을 제공한다. 특히 Banker, HR Representative, Store Clerk에게 기능별 권한을 주는 구조가 특징이다.

Class Money가 참고할 핵심은 역할명보다 권한의 분해다.
- transaction.send
- job.review
- store.review
- store.edit
같이 행동 단위 권한으로 나누고, 학생에게는 필요한 최소 권한만 임시 부여하는 방식이 적합하다.

### B. 거래 상태기계

ClassBank의 가장 독특한 구조는 교사가 거래를 '보냄'과 학생이 이를 '처리함'이 분리된다는 점이다.

교사 발행 → Pending → 학생 Deposit/Withdraw 계산 → 확정 표시

이 때문에 교사 Balance와 학생 화면의 처리된 잔액이 일시적으로 다를 수 있다.

Class Money에 이 개념을 도입한다면 이름을 더 명확히 해야 한다.
- 원장 잔액
- 학생 확인 대기
- 사용 가능 잔액
을 혼동하지 않게 한다.

또는 금액은 원장에 즉시 확정하되 학생에게 별도의 '거래 확인 활동'을 생성하는 방식이 더 단순할 수 있다. 이 방식은 금융 무결성과 학습활동을 분리한다는 장점이 있다.

### C. 교사 JTBD

ClassBank의 공식 온보딩이 보여주는 핵심 업무:
- 반 생성
- 학생 등록
- 보너스/벌금 정의
- 상점 오픈
- 직업 추가
- 청구서 추가
- 저축/이자 활성화
- 공동교사 추가

Class Money에서는 이 중 첫날 필수 작업을 학생등록 + 첫 지급 + 첫 소비처 하나로 줄이는 것이 좋다.

### D. 학생 JTBD

학생은:
- 대기 거래 처리
- 직업 탐색/지원
- 상점 구매
- 저축목표
- 거래내역 회고
를 수행한다.

이 중 ClassBank의 가장 교육적인 부분은 '수동 계산'보다 거래를 반드시 한 번 인지하게 만든다는 것이다.

Class Money는 수학 계산을 끈 경우에도:
- 이유 읽기
- 이전/이후 금액 보기
- 확인
이라는 최소 인지단계를 남길 수 있다.

### E. 경제 밸런스

공식 학년별 가격 가이드는 월급, 비용, 상점가격의 상대적 비율을 제시한다.

Class Money는 이를 고정 추천값이 아니라 밸런스 계산기로 일반화해야 한다.

필요 입력:
- 정기소득
- 고정지출
- 평균 추가소득
- 저가/중가/고가 상품
- 저축목표

출력:
- 필수지출 후 잔여비율
- 대표 상품 구매 예상기간
- 보너스 없이 유지 가능한지
- 직업 없는 학생도 참여 가능한지

### F. 상점 상태전이

학생은 pending을 처리한 뒤 구매하고, 교사는 구매를 승인/거절하며 거절 시 환불한다.

Class Money에서는 상태를 더 명확히:
상품보기 → 주문요청 → 자금예약 → 승인 → 전달완료
또는 거절 → 자금해제

실물 보상과 디지털 보상은 전달완료 기준이 다르므로 상품 유형을 데이터로 구분한다.

### G. 직업시장

1~3지망과 선택적 이력서는 단순 직업표보다 훨씬 교육적이다.

추가로 Class Money는:
- 직업 순환 주기
- 공정배정 모드
- 지난 희망/배정 이력
- 동일 학생의 인기직업 반복독점 방지
를 제공할 수 있다.

교사가 직접 배정하는 방식과 학생지원 방식을 동시에 지원해야 저학년부터 고학년까지 대응 가능하다.

### H. 회고 엔진

Bank Statement Reflection은 Class Money에 매우 중요한 설계참조다.

Class Money는 거래데이터에서 자동으로:
- 고정수입
- 추가수입
- 필수지출
- 선택지출
- 저축
- 순변화
를 계산하고 학생은 그 위에서 이유와 다음 계획만 작성하게 할 수 있다.

즉 데이터 정리는 시스템이 하고 판단과 회고는 학생이 한다.

### I. 실패모드

- Pending이 너무 많이 쌓임
- 학생이 수학 확인을 못해 상점 사용 불가
- 교사와 학생 잔액 표시 불일치
- 상점 거절 후 환불 누락
- 자동이자 지급주기 오해
- Student Helper의 과도한 권한
- 직업 순환 시 지원/고용 데이터 소실

Class Money에서는 교사 홈에 '처리 대기 3일 이상' 같은 운영경고가 필요하다.

### J. 안전과 공정성

공식 ClassBank 철학은 청구서를 못 냈다고 교실자원 접근을 박탈하지 않는다고 명시한다. 이 원칙은 반드시 가져올 가치가 있다.

Class Money 정책:
경제적 실패는 학습의 재료이지 실제 학교생활의 박탈 근거가 아니다.

### K. 제품결정

Adopt:
- 단계적 온보딩
- 거래 인지/계산
- 직업 지원
- 저축목표
- 회고
- 학생 역할 위임

Adapt:
- Pending 모델
- Bills
- fines
- interest

Avoid:
- 기본 학습권을 상품화
- 벌금을 핵심 경제회수 수단으로 사용

### L. 남은 실측 질문

- Pending 10건 이상일 때 학생 UX
- 수학 OFF 설정이 개별/전체 어디까지 유연한지
- 급여 자동실행 실패 알림
- 학생 helper 화면의 실제 범위
- 상점 approval과 물품전달 구분
- 모바일/태블릿에서 거래처리 속도
- 무료/Pro의 핵심 운영차이

## V4 심층 해부 — 이중 잔액과 학습 마찰

### 1. ClassBank의 진짜 핵심은 은행 기능보다 ‘두 개의 시간’을 운영하는 것이다

공식 도움말을 보면 교사 화면의 Balance는 교사가 학생에게 보낸 모든 거래를 이미 합산한다. 반면 학생 화면의 잔액은 학생이 To Do List에서 Deposit/Withdraw를 처리한 거래만 반영한다. Pending은 아직 학생이 처리하지 않은 거래다.

즉 하나의 거래가 두 시간축에 존재한다.

- 회계 시간: 교사가 거래를 발행한 순간
- 학습 시간: 학생이 거래를 읽고 계산하여 처리한 순간

이 구조의 장점은 학생이 모든 거래를 한 번씩 인지한다는 점이다. 단점은 교사와 학생이 서로 다른 잔액을 볼 수 있다는 점이다.

Class Money의 중요한 설계 결정:
금융원장과 학습확인을 같은 상태로 묶지 않는 편이 더 안전하다.

권고안:
- 원장은 서버에서 즉시 확정
- 학생에게 별도의 거래확인 Activity 생성
- Activity는 unread → viewed → calculated/confirmed 상태
- 학생이 확인을 늦게 해도 실제 잔액 정합성은 유지
- 교사는 ‘미확인 거래’만 별도 볼 수 있음

이렇게 하면 ClassBank의 교육적 장점은 유지하면서 ‘서로 다른 잔액’이라는 인지적 혼란을 줄일 수 있다.

### 2. 거래 처리의 인지부하 분석

학생은 매 거래마다:
1. 거래 종류 파악
2. 금액 부호 파악
3. 기존 잔액 기억
4. 새 잔액 계산
5. 정답 입력
6. 결과 확인

을 수행한다.

이는 수학 연습에는 유용하지만 거래가 많을수록 수학적 피로가 금융 이해를 가릴 수 있다.

Class Money는 거래확인 난도를 네 단계로 설계하는 것이 적절하다.

- Level 0: 자동 반영 + 이유만 읽기
- Level 1: 선택형 새 잔액
- Level 2: 직접 새 잔액 입력
- Level 3: 식까지 작성

교사는 학생별이 아니라 거래 종류별로도 설정할 수 있어야 한다.
예: 직업급여는 자동, 상점 구매는 직접 계산.

### 3. Student Helper는 ‘직업’이 아니라 권한 시스템이다

Banker, HR Representative, Store Clerk는 단순한 학급 직업명이 아니다. 실제로 거래 발행, 직업 게시판 관리, 상점 승인과 수정 권한을 받는다.

여기서 Class Money가 반드시 분리해야 할 두 개념:
- classroom role: 학생의 교육적 직업
- system permission: 앱에서 실제 할 수 있는 행동

예:
학생이 ‘은행원’이라는 직업을 맡더라도 기본적으로는 설명·안내 역할만 수행.
교사가 별도로 transaction.send 권한을 켰을 때만 제한적 기능이 활성화.

추가 안전장치:
- 자기 자신에게 지급 금지
- 1회 지급 상한
- 하루 누적 한도
- 모든 행동 감사로그
- 권한 만료일
- 고액거래 교사 재승인

### 4. 직업 시장은 배정표가 아니라 작은 노동시장이다

1~3지망, 지원서, 채용, 미배정 학생 보기, 직업 초기화 기능을 합치면 ClassBank의 직업 기능은 사실상 작은 노동시장이다.

Class Money에서 추가할 수 있는 교육적 메타데이터:
- 희망순위
- 경쟁률
- 지난 기수 배정
- 현재 직업 경험 횟수
- 직업군 다양성

교사가 ‘공정 배정’ 옵션을 켜면:
- 아직 경험하지 못한 학생 우선
- 같은 인기직업 연속배정 제한
- 1지망 미배정 학생에게 다음 기수 우선권
등의 규칙을 적용할 수 있다.

### 5. 경제 밸런스는 금액 추천보다 비율 검증이 핵심

ClassBank의 학년별 예시금액은 미국 서비스 상황에 맞는 사례다. 그대로 가져오면 안 된다.

Class Money가 일반화해야 할 것은:
- 정기소득
- 필수지출
- 자유소비
- 저축가능액
- 대표 상품 가격
사이의 비율이다.

경제 설정 마법사에서 다음을 자동 계산:
- 필수지출 비율
- 대표 상품까지 필요한 지급주기
- 저축 목표 달성 가능성
- 추가 보너스 없이도 경제가 유지되는지
- 직업 미배정 학생이 구조적으로 불리한지

### 6. 실패 시나리오 트리

ClassBank형 시스템에서 특히 위험한 실패:
- Pending 거래가 수십 건 쌓여 학생이 경제활동을 포기
- 학생 계산오류 때문에 상점 접근이 사실상 차단
- 교사 Balance와 학생 Balance 차이로 분쟁
- Student Helper가 잘못된 거래 발행
- 직업 초기화 시 과거 지원/채용 이력 소실
- 이자 지급주기를 학생이 연이율로 오해
- 구매 거절 환불이 학생에게 충분히 설명되지 않음

Class Money는 이를 제품 수준에서 감지해야 한다.

교사 경고 예:
- 미확인 거래 10건 이상 학생 3명
- 7일 이상 거래확인 없음
- 학생 보조역할이 오늘 20건 이상 거래
- 저축이자율이 현재 지급주기 기준 과도함

### 7. 최종 판단

ClassBank에서 가장 가치 있는 것은 ‘은행처럼 보이는 UI’가 아니라,
거래를 학생의 학습행동으로 바꾸고 학생에게 경제 운영권한을 일부 넘긴다는 점이다.

Class Money는 이 원리를 가져오되:
- 실제 원장과 학습확인은 분리
- 시스템 권한과 직업명 분리
- 계산난도 조절
- 밸런스 자동진단
으로 한 단계 발전시키는 것이 적절하다.
