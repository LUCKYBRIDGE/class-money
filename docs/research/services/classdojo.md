# ClassDojo 심층 분석

기준일: 2026-11-08  
분석 범위: Points, Groups, Reports, Redeem 중심  
목적: 금융 앱으로서가 아니라 ‘수업 중 초저마찰 피드백 UX’ 비교

## 1. 왜 분석하는가

ClassDojo는 교실경제 앱이 아니다. 경제 기능을 분석하려는 것이 아니라, 교사가 수업 중 학생에게 즉시 피드백을 주는 인터랙션을 어떻게 최소화했는지 보기 위해 분석한다.

Class Money에서 지급 UX가 복잡하면 수업 흐름을 깨뜨린다. 이 문제는 ClassDojo가 매우 잘 다룬다.

## 2. 핵심 제품 구조

확인된 Points 흐름:
- 교사가 학생/모둠을 선택
- 정의해 둔 Skill을 선택
- 점수 지급
- 보고서에는 시간·스킬·교사·지급범위·메모 등이 남을 수 있음

Groups:
- 모둠 생성
- 학생 중복 소속 가능
- 모둠에 점수를 주면 각 참여 학생 보고서에 반영

Redeem:
- 현재 point bubble의 점수를 보상에 사용
- 사용된 점수는 보고서 기록에는 남고 표시잔액에서 빠짐

Reset:
- 화면상의 point bubble을 0으로 만들지만 과거 보고서는 유지

## 3. Class Money가 배울 가장 중요한 것: 행동 시작 비용

ClassDojo의 핵심은 교사가 ‘포인트 지급 기능을 사용하기 위해 생각해야 할 것’을 줄인 데 있다.

교사가 이미 알고 있는 것:
- 누구에게?
- 어떤 행동에?

화면은 이 두 질문만 빠르게 해결한다.

Class Money의 즉시지급도:
1. 학생/모둠 선택
2. 사유 선택
3. 지급

세 단계가 기본이어야 한다.

금액이 항상 고정된 사유라면 금액 입력도 생략한다.

예:
‘교실 정리 도움 +5’ 버튼.

## 4. Skill 모델에서 Reason Template으로

ClassDojo의 Skill은 Class Money에서는 ‘지급사유 템플릿’으로 변환할 수 있다.

템플릿 속성:
- 이름
- 기본 금액
- 아이콘
- 적용 범위
- 월간 상한
- 경제화폐 지급 여부
- 메모 필수 여부

예:
도서정리 업무 +10
학급공동기여 +5
특별보너스 +5

이렇게 하면 거래내역의 사유 품질이 올라간다.

## 5. 그룹 지급

ClassDojo는 그룹에 한 번 지급하면 개별 학생 기록에 들어간다.

Class Money에서도 그룹/모둠 기능은 매우 중요하다.

단:
- 하나의 ‘그룹 계좌’로 돈을 넣는 것과
- 그룹 구성원 각자에게 지급하는 것을
명확히 구분해야 한다.

예:
‘1모둠에게 각 5 지급’
vs
‘1모둠 공동기금에 25 지급’

UI에서 문장을 완전히 다르게 표시.

## 6. 즉시 Undo

ClassDojo는 마지막 지급을 빠르게 undo할 수 있다.

Class Money에서도 지급 직후:
‘25명에게 각 5 지급 완료 — 되돌리기’
같은 snackbar/action을 제공할 가치가 크다.

하지만 내부적으로는 기록 삭제가 아니라 역거래로 처리한다.

## 7. Reports에서 배울 것

ClassDojo 보고서는 단순 총점이 아니라:
- 어떤 Skill
- 언제
- 어느 교사
- 개인/모둠/전체 중 어떤 범위
- 메모
를 보여줄 수 있다.

Class Money 거래 역시 단순 금액이 아닌 문맥을 저장해야 한다.

거래 이벤트:
- 금액
- 이유
- 생성자
- 대상 범위
- 원본 그룹
- 관련 직업/상품/과업
- 정정 여부

## 8. ‘표시 잔액’과 ‘기록’ 분리

Redeem이나 Reset에서 현재 point bubble과 역사 보고서를 분리한다.

이 개념은 Class Money에도 중요하다.

예:
학생이 보는 ‘이번 달 사용 가능액’과
감사 목적인 ‘전체 거래 원장’은 같은 것이 아니다.

단, 금융 원장에서는 reset으로 거래 자체를 없애면 안 된다.

## 9. Points를 경제화폐로 그대로 쓰면 안 되는 이유

ClassDojo의 목적은 긍정 행동 피드백이다.

Class Money의 목적은 경제적 선택 학습.

둘을 합치면:
- 교사에게 칭찬을 많이 받은 학생이 더 많은 소비권을 얻음
- 행동평가가 자산으로 축적
- -포인트가 경제적 불이익으로 누적
- ‘돈이 많은 학생 = 좋은 학생’처럼 오해 가능

따라서 Class Money는 ‘행동 피드백’과 ‘경제화폐’를 기본적으로 분리해야 한다.

## 10. Negative Points와 벌금

ClassDojo는 Skill 값을 -5~5로 설정할 수 있다.

Class Money가 이를 벌금으로 그대로 대응시키면 안 된다.

권고:
- 행동 피드백은 비금전 기록 가능
- 경제 벌금은 별도 기능이며 기본 OFF
- 활성화 시 금액 상한/이의제기/공개 금지

## 11. 포인트 공개 범위에서 배울 것

ClassDojo는 교사가 가족에게:
- 전체 포인트
- 긍정 포인트만
- 포인트 미공개
를 선택할 수 있다.

Class Money도 공개범위 설정이 필요하다.

학생:
- 자기 잔액/거래만

학급:
- 개인별 자산은 기본 비공개

보호자/가정 연동을 나중에 제공한다면:
- 잔액
- 요약
- 목표
- 거래 상세
를 각각 별도로 공유 설정.

## 12. Class Money에 가져올 것

강하게:
1. 학생 타일 기반 빠른 선택
2. 그룹 지급
3. 사유 템플릿
4. 지급 직후 Undo
5. 보고서에 문맥 기록
6. 공개범위 설정
7. 현재 표시값과 역사 데이터 분리

가져오지 않을 것:
- 행동 포인트를 경제화폐의 주 수입원으로 사용
- -포인트를 자동 벌금으로 변환
- 공개 총점 경쟁을 경제 잔액 경쟁으로 변환

## 13. Craft Anything 후속 실측

- 개인 지급 클릭 수
- 그룹 지급 클릭 수
- 전체 지급 클릭 수
- Skill 편집
- Undo 타이밍
- Reports 탐색
- 모바일 화면에서 학생 타일 밀도
- 프로젝트 화면으로 띄웠을 때 피드백 가시성

## 14. 현재 판단

ClassDojo는 Class Money의 경제 모델 참고 대상이 아니라 ‘교사가 수업을 멈추지 않고 데이터를 입력하는 방법’의 벤치마크다.

Class Money는 경제 엔진은 더 엄격하게, 수업 중 지급 UI는 ClassDojo 수준으로 가볍게 만드는 것이 적절하다.
