# 토스 유스 심층 분석

기준일: 2026-11-08  
분석 목적: 한국 어린이·청소년 금융 UX, 잔액·소비 회고·보호자 기능 참고  
주의: 토스 유스는 실제 금융 서비스이며 Class Money는 이를 복제하거나 실제 결제와 연동하지 않는다.

## 1. 왜 분석하는가

Class Money가 한국 초등학생을 대상으로 한다면 해외 아동금융앱만 보는 것은 부족하다.

토스 유스는 한국 청소년에게:
- 카드
- 충전
- 송금
- 소비 내역
- 용돈기입장
- 저금
- 보호자 기능
을 실제 생활 맥락에서 제공한다.

Class Money가 참고할 것은 금융상품이 아니라 ‘어린 사용자에게 돈을 어떻게 설명하고 보여주는가’이다.

## 2. 제품 정체성

공식 페이지는 ‘어릴 때부터 스스로 배우는 나의 첫 금융 생활’을 중심 메시지로 둔다.

확인되는 주요 경험:
- 자신의 이름이 있는 유스카드
- 충전한 만큼만 사용
- 용돈기입장
- 소비 내역 확인
- 목표를 세워 모으기
- 친구 송금과 메시지
- 보호자 용돈 보내기 및 카드 관리
- 미성년자 특화 한도와 승인

## 3. ‘충전한 만큼만 쓴다’는 경계 설계

유스카드는 보유 잔액 범위 내에서 사용되고 잔액이 부족하면 결제가 거절된다.

Class Money에도 이 원칙이 기본으로 적합하다.

기본 지갑:
- 음수 잔액 금지
- 남은 금액보다 큰 구매 거절
- 대출/부채는 별도 시뮬레이션 기능에서만 허용

장점:
학생이 ‘쓸 수 있는 돈’의 경계를 직관적으로 이해한다.

## 4. 용돈기입장

공식 소개는 돈을 어디에 얼마나 썼는지 한눈에 보여주고, 평소보다 많이 쓴 날이나 아낄 수 있는 내역을 보여줘 스스로 소비습관을 돌아보게 한다고 설명한다.

Class Money에서 매우 중요한 패턴:
거래내역은 ‘장부’로 끝나지 않고 회고를 유도해야 한다.

학생 화면:
- 이번 주 수입
- 이번 주 지출
- 가장 많이 쓴 항목
- 지난주보다 달라진 점
- 목표에 미친 영향

교사에게는 개인 소비내역 공개가 아니라 학급 전체 익명 요약을 우선.

## 5. 실제 결제 앱의 정보 우선순위

실제 금융앱에서는 사용자가 가장 자주 알고 싶은 것이:
1. 지금 얼마 있는가?
2. 최근 어디에 썼는가?
3. 문제가 생겼는가?
이다.

Class Money 학생 홈도 경제 기능 메뉴를 앞에 나열하기보다:
- 사용 가능액
- 최근 거래
- 목표
- 다음 예정 소득
을 우선 배치하는 것이 자연스럽다.

## 6. 목표와 저축

공식 틴즈 소개는 목표를 세워 용돈을 모으는 경험을 강조한다.

Class Money에서 목표는 단순 숫자보다 실제 의사결정에 연결:
‘지금 구매하면 목표까지 예상 기간이 어떻게 바뀌는가’
를 보여준다.

## 7. 보호자 전용 기능에서 배우는 권한 분리

토스는 자녀와 보호자의 기능이 다르다.

Class Money:
학생과 교사의 화면은 같은 앱의 ‘축소판’ 관계가 아니어야 한다.

교사:
- 경제 정책
- 승인
- 정정
- 전체 장부
- 경제 건강

학생:
- 자기 지갑
- 자기 목표
- 자기 직업
- 구매
- 회고

교사의 전체 권한을 학생 메뉴에서 단순 숨기는 수준보다 서버 권한을 완전히 분리해야 한다.

## 8. 미성년자 한도에서 얻는 설계 원리

실제 금융 서비스는 연령에 따라 송금·보유·사용 한도를 둔다.

Class Money에는 실제 법적 금융한도가 필요하지 않지만 ‘한도’라는 제품 원리는 유용하다.

교사 설정:
- 1회 학생 간 송금 한도
- 하루 지급 한도
- 보조 학생의 지급 한도
- 상품 1일 구매 수량
- 과업 추가보수 월간 상한

한도는 사고·악용을 줄이는 안전장치다.

## 9. 친구 송금의 양면성

토스 틴즈는 친구 송금과 메시지를 제공한다.

실제 생활에서는 자연스러운 기능이지만 교실경제에서 학생 간 자유송금은 위험하다.

가능한 문제:
- 강요
- 빌려주기 분쟁
- 비공식 거래
- 인기/관계에 따른 돈 이동
- 교사의 사후 확인 어려움

따라서 Class Money 기본값:
학생 자유송금 OFF.

향후:
- 승인형 송금
- 목적 선택
- 금액 상한
- 교사 감사로그
를 포함한 P2 기능으로 검토.

## 10. 소비 회고 UX

토스의 용돈기입장 관점은 Class Money에 매우 적합하다.

단순 ‘이번 달 300 사용’보다:
- 지난주보다 20 더 썼어요
- 상점 구매 3회
- 목표저축 1회
- 가장 큰 소비 80
처럼 패턴을 보여준다.

하지만 ‘과소비’ 같은 가치판단을 자동으로 단정하지 않는다.

교실경제에서는 교사가 만든 가격 자체가 임의적이기 때문이다.

## 11. Class Money에 가져올 것

강하게:
1. 사용 가능액 중심 첫 화면
2. 최근 거래 우선
3. 소비 요약/회고
4. 목표 저축
5. 역할별 화면 완전 분리
6. 금액/행동 한도
7. 잔액 부족 시 명확한 차단

신중:
- 친구 송금
- 메시지와 거래 결합

제외:
- 실제 카드
- 실제 결제
- 실제 송금
- 오픈뱅킹/계좌 연동

## 12. Craft Anything 후속 실측

실제 접근 가능한 공개/본인 계정 범위에서만:
- 틴즈 홈 정보계층
- 용돈기입장의 카테고리 표현
- 목표저축 화면
- 잔액 부족 피드백
- 보호자/자녀 화면의 차이
- 거래 상세의 정보량
- 모바일 한 손 조작

## 13. 현재 판단

토스 유스에서 가져올 것은 ‘금융 기능’이 아니라 한국 어린 사용자가 돈을 이해하는 화면 언어다.

Class Money는 경제 시뮬레이션이더라도 학생 화면만큼은 실제 금융앱처럼:
간단하고, 잔액 경계가 명확하고, 최근 행동과 목표가 바로 보여야 한다.

## 심화 보완: 12개 분석축

### A. 사용자와 권한
토스 유스는 미성년 실제 금융이므로 보호자 동의와 실제 계정 경계가 존재한다. Class Money는 이 법적 구조를 복제하지 않지만 '학생화면과 관리자화면을 완전히 다른 목적에 맞게 설계'하는 원칙은 가져올 수 있다.

### B. 핵심 객체
Class Money에 직접 참고할 객체:
- wallet
- transaction
- category
- savings goal
- guardian/teacher control

실제 card/account 객체는 제외한다.

### C. 소비 회고
용돈기입장의 가치는 원장 자체보다 패턴을 보여주는 것이다.

Class Money는 학생에게:
- 벌기
- 쓰기
- 모으기
세 카테고리부터 시작하고 세부 사유는 하위에서 보여주는 편이 이해하기 쉽다.

### D. 목표저축
해냄 저금통처럼 목표가 시각적으로 선명할수록 저축의 의미가 살아난다.

Class Money 목표 카드:
- 목표 이미지/아이콘
- 현재/목표
- 남은 금액
- 최근 저축
- 예상 달성주차

### E. 감정적 목표와 금융행동
덕질 저금통의 핵심 원리는 좋아하는 대상과 저축을 연결하는 것이다.

교실에서는 학생이 직접 goal icon/title을 만들되, 공개될 경우 교사 검토와 개인정보 필터가 필요하다.

### F. 사회적 기능
공개 댓글·메시지가 붙는 순간 moderation이 필요해진다.

Class Money MVP에서:
- 공개 댓글 없음
- DM 없음
- 상점 후기 없음

경제기능 안정화 후 별도 소셜 안전설계가 있을 때만 도입한다.

### G. 선불 경계
충전한 만큼만 사용한다는 단순 경계는 초등 교실경제에 매우 적합하다.

기본 wallet:
balance >= purchase amount 이어야 함
debt는 별도 학습모듈

이 경계를 UI와 서버 양쪽에서 검증한다.

### H. 알림과 안전
실제 금융앱은 거래 결과를 명확히 알리는 것이 신뢰의 핵심이다.

Class Money도 지급/구매/환불 후:
- 얼마
- 왜
- 잔액
- 상태
를 즉시 알려야 한다.

### I. 국내 사용자 언어
학생에게 debit/credit 같은 용어보다:
- 들어온 돈
- 쓴 돈
- 모은 돈
을 먼저 쓰고, 학습모드에서 정식 경제용어를 병기하는 것이 적합하다.

### J. 실패모드
- 목표를 삭제했을 때 돈 이동
- 결제와 동시에 다른 거래 발생
- 잔액 부족
- 보호/교사 승인대기
- 세션이 공유기기에 남음

실제 금융앱 수준의 명확한 상태문구가 필요하다.

### K. 제품결정
Adopt:
- 잔액 중심 홈
- 최근거래
- 소비회고
- 목표저축
- 명확한 잔액부족

Adapt:
- 역할별 화면
- 한도

Avoid:
- 실제 금융연동
- 자유송금 기본 ON
- 소셜 금융기능 초기 도입

### L. 남은 실측
- 홈 카드 우선순위
- 용돈기입장 category depth
- goal 생성단계
- 잔액부족 문구
- 미성년 사용자용 숫자 표현
- 보호자 화면과 자녀 화면 차이

## V4 심층 해부 — 한국 초등학생에게 보이는 금융 언어

### 1. 토스에서 중요한 것은 실제 금융기능이 아니라 문장의 난도다

공식 틴즈 페이지는 어려운 계좌용어보다:
- 어디에 얼마나 썼는지
- 목표까지 얼마나 남았는지
- 충전한 만큼만 쓸 수 있는지
를 직접 설명한다.

Class Money 학생 UI에서도 내부 회계용어를 그대로 노출하지 않는다.

내부:
transaction, debit, credit, ledger

학생:
들어온 돈, 쓴 돈, 모은 돈, 남은 돈

고학년 학습모드에서 정식 용어를 병기할 수 있다.

### 2. 용돈기입장은 거래목록보다 패턴이다

토스는 단순 목록보다 평소보다 많이 쓴 날, 아낄 수 있는 내역처럼 소비패턴을 돌아보게 한다.

Class Money는 가치판단을 자동으로 내리지 않되:
- 이번 주 가장 큰 소비
- 지난주보다 지출 증가/감소
- 저축 횟수
- 상점 구매 횟수
를 보여줄 수 있다.

교실 가격은 교사가 만든 임의 화폐이므로 ‘과소비’ 같은 도덕적 판정은 피한다.

### 3. 해냄 저금통의 핵심은 남은 거리다

초등학생에게 65%보다:
‘35코인 더 모으면 돼요’
가 더 직접적일 수 있다.

Class Money Goal은:
- 현재액
- 목표액
- 남은액
- 예상 몇 번의 급여가 필요한지
를 함께 보여준다.

### 4. 덕질 저금통이 보여주는 소셜 위험

공식 유의사항에는 비속어, 전화번호 등 개인정보, 신고 누적, 관리자 숨김/삭제 정책이 있다.

즉 목표저축에 댓글/공개기능을 붙이는 순간 금융앱이 콘텐츠 플랫폼이 된다.

Class Money 초기에는:
- 공개 댓글 없음
- DM 없음
- 자유 후기 없음

목표/상점 소셜기능은 moderation 체계가 준비된 뒤 별도 검토한다.

### 5. 최종 판단

토스에서 가져올 것은:
한국 어린 사용자가 숫자와 거래를 이해하는 정보계층과 문장이다.

Class Money 학생화면은 경제 시뮬레이션의 복잡성을 감추고:
잔액 → 변화 → 목표 → 다음 행동
순으로 단순하게 보여주는 것이 적절하다.
