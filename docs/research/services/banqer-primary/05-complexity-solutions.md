# Banqer Primary — 얽힌 문제와 해결방식

## 복잡한 문제를 어떻게 풀었는가

| 얽힌 문제 | 서비스의 해결방식 | Class Money에 번역 |
|---|---|---|
| 고급 경제개념이 한꺼번에 노출 | Expansion 단위 단계개방 | 기능 ON/OFF가 아니라 학습모듈 카드로. |
| 기능은 있지만 지금 수업에서 쓰지 않음 | Enabled와 Open/Closed 분리 | Class Money도 Module Enabled와 Activity Open 분리. |
| 결제와 실제 보상수령이 다름 | My Stuff/Claim | Payment status와 Fulfillment status 분리. |
| 수업자료와 앱이 분리될 수 있음 | 개념별 기능+학습자료 결합 | 설정/학생화면/수업자료/시작을 같은 모듈에. |
| 성인금융 재현이 과도할 수 있음 | 단계적 Expansion | 초등에서는 원리만 가상 시나리오로 변환. |

## 평가 기준

좋은 해결방식인지 판단할 때:
- 교사 클릭 수만 줄였는가, 아니면 오류복구도 쉬운가?
- 학생에게 필요한 사고까지 자동화해 없애지는 않았는가?
- 다수 학생에게 적용할 때 batch/exception을 처리할 수 있는가?
- 역할/권한/경제상태가 섞여 있지 않은가?
- 정상경로뿐 아니라 실패·취소·환불·정정도 정의돼 있는가?
- 기능이 증가해도 기본 사용자에게 복잡도가 전파되지 않는가?
