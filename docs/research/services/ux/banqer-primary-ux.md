# Banqer Primary — 복잡성·정보구조·UI·UX 심층 분석

기준일: 2026-11-08  
증거 수준: 공식 How it works/Help에서 모듈과 Class Store 흐름 확인. 전체 앱 실측 전.

## 1. 복잡성의 원천
소득, 지출, 직업, 은행, 이자, 정기예금, 세금, 자산, 보험, 교통 등 서로 다른 금융 개념을 하나의 학급 시뮬레이션에 담는다. 이 범위에서는 단순 메뉴 나열보다 학습 단계 중심 구조가 필요하다.

## 2. 핵심 해법: Expansion/Module 사고
경제 기능을 개념별 확장으로 본다. 학생은 소득 → 지출 → 직업 → 은행 → 저축 → 세금 → 자산처럼 경제 세계를 점진적으로 확장한다.

Class Money는 기능 토글 목록보다 학습 단계 화면으로 번역하는 것이 좋다.

## 3. 권고 정보구조
1단계 돈의 흐름: 기본소득 / 상점  
2단계 계획: 직업 / 저축 / 목표  
3단계 공동체: 세금 / 국고  
4단계 시장: 창업 / 공급수요 / 경매

학생에게는 현재 활성화된 단계만 보인다.

## 4. Class Store 흐름
공식 Help에서 학생은 대시보드의 Store에서 장바구니 → checkout → payment 흐름을 사용하고, 교사는 상점을 열고 닫고 교사 상품 claim을 처리할 수 있다.

UI적으로 중요한 것:
- 상점의 현재 상태를 명확히 보여주기.
- 품절/닫힘/승인대기를 서로 다른 상태로 표현.
- 장바구니에서 결제 전 금액을 다시 확인.

## 5. 학습자료를 문맥에 붙이기
Banqer는 금융기능과 영상·퀴즈·그룹활동을 함께 제공한다.

Class Money는 세금 화면에서 처음 켤 때 10분 수업카드, 학생 첫 진입에서 2~3장 미니 설명을 제공하는 방식이 적합하다. 별도 자료실보다 기능 문맥 속 진입이 좋다.

## 6. 정보밀도 제어
기능이 많아져도 학생 홈은 4개 이하 핵심 지표를 유지한다.
- 사용 가능
- 이번 주 변화
- 목표
- 오늘 할 일

자산·보험·세금 상세는 내 경제 상세로 내려간다.

## 7. 미래 영향 UX
장기 금융기능은 행동 전 결과를 보여줘야 한다.

예:
4주 잠금저축 → 이 기간 동안 사용 불가  
세금 설정 → 다음 징수 후 국고 예상액  
보험 가입 → 지금 비용과 보호되는 위험

## 8. UX 위험
- 확장 모듈이 많아지면 홈 정보량 증가.
- 실제 금융용어가 저학년에 과도.
- 학습 퀴즈 보상이 자산 격차로 이어질 수 있음.
- 교사가 무엇부터 켤지 모를 수 있음.

## 9. Class Money 적용
- 단계형 기능개방
- 첫 진입 미니 설명
- 교사용 문맥형 수업카드
- 상점 상태 명시
- 미래 영향 미리보기
- 학생 홈 지표 제한
- 활성화 순서 추천
