# My Classroom Economy — 복잡한 기능을 물리적 절차로 풀어낸 방식 분석

기준일: 2026-11-08  
성격: 전통적인 교실경제 프로그램. 최신 웹앱 UI보다 오프라인 UX와 서비스 흐름 분석이 중요.

## 1. 복잡성의 원천
직업, 급여, 은행, 월세, 벌금, 보너스, 대출, 경매, 장부, 임대계약, 자산소유가 모두 종이 문서와 역할 분담으로 얽힌다.

디지털 앱이라면 메뉴와 상태로 풀 문제를 이 프로그램은:
- 폴더
- 은행원
- bank log
- bank slip
- paycheck
- rent log
- auction record
- rental agreement
같은 물리적 객체로 풀었다.

## 2. 이 서비스의 진짜 UX: 역할과 문서
각 복잡한 경제행동을 하나의 양식과 역할에 대응시킨다.

예:
급여 → paycheck  
입출금 → bank slip + bank log  
월세 → rental agreement + rent log  
벌금 → fine ticket  
경매 → paddle + auction record

이 방식의 장점은 학생이 추상적 시스템 상태를 물리적으로 볼 수 있다는 점이다.

## 3. 은행 흐름의 UX
학생이 거래를 기록하고 Banker가 별도 기록을 확인한다.

이중 기록은 느리지만:
- 학생이 직접 계산
- 상대방 확인
- 기록 대조
라는 교육 경험을 만든다.

Class Money는 내부적으로 자동 원장을 쓰되 학생에게는:
예상잔액 → 거래 → 결과 확인
의 학습 단계는 남겨야 한다.

## 4. 상태를 문서로 표현
현대 앱에서는 Pending/Completed/Rejected로 표시할 것을 이 프로그램은:
- unpaid rent notice
- paid 표시
- signed job offer
- signed rental agreement
처럼 물리적 문서 상태로 표현한다.

Class Money는 이 명확성을 디지털 상태 라벨로 가져와야 한다.

## 5. 경매 UX
실제 패들, 공개 입찰, Assistant Auctioneer 기록, 낙찰 후 현금 인출·지불이라는 순차적 의식이 있다.

복잡하지만 각 단계가 분명하다.

Class Money의 경매 모듈을 만든다면:
상품 보기 → 내 예산 확인 → 입찰 → 최고입찰 hold → 낙찰/패배 → 결제
순서를 축약하지 말아야 한다.

## 6. 월간 Cadence
매달 급여, rent, fine/bonus, auction이 반복된다.

이 리듬 덕분에 사용자는 기능을 메뉴로 기억하지 않고 달력의 반복행동으로 기억한다.

Class Money 교사 홈은 메뉴뿐 아니라:
이번 주 / 이번 달 예정
을 강하게 보여줄 필요가 있다.

## 7. 물리적 산출물에서 배울 점
디지털 앱이라도 출력 가능한:
- 급여명세서
- 직업카드
- 통장
- 거래명세
- 학급 경제규칙
- 세금/국고 보고서
를 제공하면 교실 벽과 오프라인 수업으로 연결된다.

## 8. UX적으로 문제가 되는 부분
- 수기 절차가 많아 교사/학생 시간이 많이 필요.
- 장부 분실/오류.
- Banker 역할 학생에게 업무가 과도할 수 있음.
- 월세 미납과 경매 참여 제한이 학생 낙인으로 이어질 수 있음.
- 실제 자리 소유/임대는 학습환경 공정성 문제.

## 9. Class Money 적용
자동화할 것:
- 합산
- 중복검증
- 급여실행
- 장부 보관
- 환불
- 통계

남길 것:
- 선택
- 예상
- 기록 의미
- 역할
- 회고
- 오프라인 출력물

## 10. Craft Anything/문서 분석 항목
이 서비스는 웹 UI보다 자료 흐름을 분석한다.
- 홈페이지에서 각 자료를 찾는 탐색구조
- 직업/은행/월세/경매 자료의 연결
- 인쇄물 한 장이 어떤 행동을 담당하는지
- 교사 준비물과 학생 준비물 분리
- 월간 운영 순서
