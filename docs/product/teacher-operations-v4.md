# 교사 운영 시스템 v4

## 1. 제품의 첫 번째 현실 문제

교실경제는 교육적으로 좋아도 교사가 유지하지 못하면 끝난다.

분석한 서비스 중:
- ClassCents는 setup/Payday 자동화
- Cashroom은 통합 Alert Bell
- ClassDojo는 빠른 학생 선택
- ClassCoin은 점수판과 반복업무 자동화
가 이 문제를 서로 다른 방식으로 푼다.

Class Money 교사용 제품의 목표는 ‘경제기능 관리’가 아니라 ‘25명 학급의 반복 의사결정 최소화’다.

## 2. 교사 홈 구조

첫 화면 우선순위:

### 오늘 처리할 것
구매 승인
직업 지원
퀘스트 승인
실패한 자동급여
잔액/정책 경고

### 빠른 지급
최근 학생/모둠
최근 사유
최근 금액

### 예정
다음 Payday
다음 세금
상점 이벤트
경매

### 경제 건강
발행량
회수량
중앙잔액
대표상품 구매기간
직업 미배정

통계차트보다 action queue가 위에 온다.

## 3. 교사 업무를 빈도로 나눈다

High frequency:
- 학생 지급
- 승인
- 잔액 확인

Medium:
- 직업
- 상점
- 목표/저축

Low:
- 세금정책
- 이자율
- 학기이관
- 시장/대출 모듈

메뉴 구조도 빈도에 맞춘다.

## 4. 빠른 지급

목표 인터랙션:
대상 → 사유/금액 → 지급

확인모달을 항상 띄우지 않는다.

2차 확인 조건:
- 전체 학급
- 큰 금액
- 차감
- unusual transaction

지급 후 Undo 토스트.

## 5. Teacher Inbox

모든 대기 요청을 공통 큐에 모은다.

타입:
ORDER
JOB_APPLICATION
TASK_APPROVAL
TRANSFER
LOAN
MARKET_LISTING
SYSTEM_ERROR

필터:
오늘 / 오래됨 / 고위험 / 학생

Batch action:
동일 조건 요청 여러 건 승인 가능.

단, 학생별 최종 결과는 각각 원장에 남긴다.

## 6. 설정 마법사

첫날:
1. 학생 붙여넣기
2. 화폐 이름
3. 지급주기
4. 직업 starter 선택
5. 상점 starter 선택
6. 첫 지급

고급 경제 설정은 숨긴다.

## 7. 경제 규칙을 바꿀 때

단순 저장하지 않고 영향 미리보기.

예:
주급 50 → 40

표시:
- 예상 자유금액
- 대표상품 달성기간
- 구조적 적자 학생
- 다음 적용일
- 이미 확정된 급여 영향 없음

ClassCoin의 세금 영향미리보기 패턴을 경제 전반에 일반화한다.

## 8. 교사 운영부하 지표

제품 자체에서 측정 가능한 익명 UX 지표:
- 주당 교사 action 수
- batch 처리 비율
- 자동화 성공률
- undo 비율
- 오래된 pending 요청
- 학생 로그인 지원 요청 빈도

목표는 기능사용량을 늘리는 것이 아니라 반복업무를 줄이는 것이다.

## 9. 실패 복구 화면

실패하면 ‘오류’만 보여주지 않는다.

예:
금요일 급여 25명 중 23명 성공

화면:
성공 23
실패 2
이유
재시도 버튼

재시도 시 성공 23명은 idempotency로 제외.

## 10. 학기 종료

경제 종료:
- 예약작업 중지
- 대기요청 처리/취소
- 마지막 statement
- export
- archive

삭제와 종료를 분리한다.

## 11. 운영 성공 기준

실제 파일럿에서 검증할 목표:
- 25명 등록
- 첫 지급
- 주간 자동급여
- 10건 주문승인
- 오지급 복구
를 교사가 설명서 없이 수행 가능한가.

이 다섯 작업이 안정적이지 않으면 고급금융 기능은 출시하지 않는다.
